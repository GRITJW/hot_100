    • 段落保持密度：每段 4–8 句中文，避免单句成段
    • 示例优先于定义：抽象概念尽量用具体例子先建立直觉，再上升为定义
    • 代码块前后必须有解释：不允许出现"上代码"式的甩代码

    2.2 不允许的失误¶

    • 错把 HBM 当作 GPU-GPU 通信方式（HBM 是 GPU 本地显存技术）
    • 错说"CUDA 把 Python 翻译成 GPU 程序"（CUDA 是承接具体张量算子的运行时与库）
    • 错说大块数据从 CPU Cache/Register 传到 VRAM（实际是 RAM → PCIe → VRAM）
    • 错说 PCH/芯片组是计算单元（它是外围 I/O 管理中心）
    • 错把 NVLink 描述为"更快的 PCIe"（它是不同协议、不同拓扑的独立互联）

    详见第 8 节"关键误区清单"。

    3. 全文骨架与设计哲学¶

    3.1 五视角递进¶

    本笔记的组织原则不是"按硬件组件切片"，而是按视角递进。每一个 Part 是对前一个 Part 的纵深化，而不是平行内容。这条主线是本笔记区别于普通硬件百科的关键。

    Part 视角 核心问题 类比
    I 空间视角 硬件长什么样？在哪里？怎么物理连接？ 看一张城市卫星图
    II 单元视角 每个建筑物里面有什么？各自擅长什么？ 走进每栋楼内部
    III 执行视角 一段代码运行时，数据如何在城市里流动？ 跟踪一辆车的轨迹
    IV 性能视角 哪条路最容易堵？为什么堵？ 交通流量分析
    V 实践视角 如何调度才能让车跑得最快？ 路线规划

    3.2 主线一以贯之的两条隐线¶

    除了视角递进，全书还有两条隐线，要求执行者在写作时持续意识到：

    隐线 A：所有性能问题都是互联问题。 计算单元从来不是瓶颈本身，而是"喂不饱计算单元"造成了瓶颈。CPU↔Cache、CPU↔RAM、GPU↔HBM、CPU↔GPU、GPU↔GPU、节点↔节点，每一层互联都可能成为木桶的最短板。这条隐线在 Part I 第 4 章建立，在 Part II 第 8 章深化，在 Part IV 几乎每一章都被复用。

    隐线 B：控制流与数据流的分工。 CPU 是控制流的统帅，GPU 是数据流的劳工。这条对照在第 5 章和第 6 章首次建立，在第 9 章（软件栈）和第 10 章（执行旅程）中被反复引用。它解释了为什么 CUDA 不是把整段 Python 翻译成 GPU 程序——因为控制流仍然由 CPU 主导，GPU 只承接被分派下来的数据流任务。

    8. 关键误区清单¶

    执行者在写作过程中必须显式避免以下五个常见误区。建议在写到相关章节时，回查本清单。

    8.1 HBM 不是 GPU-GPU 通信方式¶

    HBM（High Bandwidth Memory）是一种 GPU 本地显存技术，特点是堆叠式封装、宽位宽、低能耗。它是 GPU↔自身显存 的通道，不是 GPU↔GPU 的通信方式。

    GPU↔GPU 通信靠的是 NVLink、NVSwitch、PCIe、或网络互联。

    涉及章节：第 3 章、第 6 章、第 7 章、第 8 章。

    8.2 CUDA 不是把整段 Python 翻译成 GPU 程序¶

    CUDA 是一套包含运行时（Runtime）、驱动（Driver）、库（cuBLAS、cuDNN、NCCL）的软件栈。它的工作是承接被分派下来的具体张量算子，把这些算子的执行交给 NVIDIA GPU。

    Python 解释器、训练循环控制流、模型结构定义这些都仍然由 CPU 执行。

    涉及章节：第 9 章、第 10 章。

    8.3 大块数据不是从 CPU Cache/Register 传到 VRAM¶

    CPU 到 GPU 的大块数据传输路径是：系统内存 RAM → PCIe → 显存 VRAM。

    CPU Cache 和 Register 是 CPU 访问内存时的高速缓冲，容量极小（KB–MB 级），不是模型权重等大块数据的存储与中转地点。

    涉及章节：第 7 章、第 10 章。

    8.4 PCH 不是计算单元¶

    PCH（Platform Controller Hub）是主板上的外围 I/O 管理芯片，负责 USB、SATA、音频、低速网卡等接口。它不进行任何深度学习相关的计算，也不是 GPU 训练算力的瓶颈来源。

    PCH 可能影响的是：磁盘 I/O 速度、外设访问延迟。

    涉及章节：第 1 章、第 4 章。

    8.5 NVLink 不是"更快的 PCIe"¶

    NVLink 是 NVIDIA 自有的高速互联协议，与 PCIe 是不同协议、不同拓扑、不同物理层。NVLink 与 PCIe 在系统中并存而非替代：GPU 仍然通过 PCIe 与 CPU/系统内存通信，NVLink 主要用于 GPU↔GPU（部分场景下 GPU↔CPU）。

    涉及章节：第 4 章、第 8 章。
